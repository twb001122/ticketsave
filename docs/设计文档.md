# TicketSave 设计文档

## 1. 设计定位

产品视觉关键词：

- 收藏感
- 档案感
- 演出氛围
- 液态玻璃
- 高级但不过度花哨

这款 app 不走传统工具型后台风格，而是以“个人演出档案馆”为核心体验。  
界面应该让用户感受到自己正在整理一段可被珍藏的演出生涯，而不是填写一张冷冰冰的表单。

## 2. 视觉原则

### 2.1 暗色主题

暗色是主主题，延续当前“舞台夜场”方向：

- 深黑与深灰背景
- 暖橙与紫粉作为强调色
- 玻璃、辉光、柔和阴影增强层次

### 2.2 亮色主题

亮色不做纯白工具风，而是采用偏暖的浅底：

- 米白 / 奶油白背景
- 深墨色文字
- 暖珊瑚、天青、莓紫作为强调色
- 减弱过重的紫蓝渐变，保持高级感与柔和感

### 2.3 玻璃语义

玻璃层用于：

- 统计摘要
- 卡片信息遮罩
- 主信息卡
- 设置入口卡
- 关键操作按钮

玻璃设计要求：

- 不做厚重塑料感
- 不做过黑过灰的统一蒙层
- 尽量让玻璃受到背景内容的轻微影响
- 明暗主题下都要可读

## 3. 信息架构

### 首页 Archive

结构顺序：

- 统计摘要
- 筛选栏
- 演出卡片列表

设计重点：

- 统计摘要提供轻量信息密度
- 筛选操作必须方便且命中区域清晰
- 卡片要有海报感和票卡感的结合

### 演出详情

详情页采用“海报沉浸型”：

- 顶部是通栏封面图
- 下方信息区压在封面下半部
- 通过渐变让图片自然融入背景

结构顺序：

- Hero 封面
- 主信息卡
- 三张关键信息卡
- 更多资料
- 阵容
- 备注

## 4. 首页卡片设计

### 设计目标

- 一眼可识别是“演出卡”
- 有票根与海报融合感
- 保持信息清晰，不做重复标题

### 当前策略

- 上半部展示封面
- 下半部是独立信息层
- 信息层采用玻璃语义
- 时间、地点、类型等信息做压缩布局

### 需要长期保持的原则

- 不让信息遮罩出现无意义高度
- 不让文字在遮罩中出现偏上/偏下失衡
- 毛玻璃不应完全退化成普通半透明色块

## 5. 详情页设计

### 5.1 Hero 区

- 封面图需通栏，包括状态栏区域
- 图像底部用长渐变过渡到页面背景
- 上层信息不应被图像影响阅读

### 5.2 主信息卡

目标是成为详情页视觉重心：

- 标题保持左对齐
- 厂牌放在标题同行右侧
- 第二行集中放三枚标签：
  - 内容形式
  - 我的角色
  - 演出属性

要求：

- 高度尽量由内容驱动
- 不出现无意义留白
- 和 Hero 之间形成“展签浮层”感

### 5.3 三张关键小卡

固定展示：

- 日期时间
- 剧场
- 城市地点

设计要求：

- 三张卡高度保持一致
- 内部元素居中
- 文本层级统一
- 不保留无意义标题行
- 副值可带强调色，帮助快速识别

### 5.4 更多资料

设计要求：

- 一栏式结构
- 左侧：icon + key
- 右侧：value
- 不和关键小卡重复
- 重点是补充档案信息，而不是抢视觉中心

### 5.5 阵容区

- 使用横向卡片而非纵向列表
- 只展示名字，不展示“职业/角色”
- 卡片底色与整体背景保持融合

## 6. 设置中心设计

设置中心是功能入口页，不是传统系统列表页的机械复制。

结构：

- Hero 文案
- 外观切换
- 设置入口卡

入口卡当前包括：

- 实体管理
- 本地备份

设计要求：

- 可延展
- 保持轻量
- 和首页、详情页属于同一套设计语言

## 7. 实体管理设计

设计目标：

- 管理关系清晰
- 操作简单
- 避免按钮拥挤

因此当前策略是：

- 上方三类实体用更大的切换 tab
- 实体行保持简约
- 行内不再长期摆放编辑/删除按钮
- 统一通过左滑唤出编辑 / 删除操作

## 8. 图标设计

当前应用图标采用“票根 / 门票”方向：

- 主体是极简票根图形
- 配色柔和，带暖米色与浅棕灰背景
- 目标是传达“收藏票根”的产品核心意象

## 9. 未来设计演进

- 统计页可继续沿用档案馆视觉，而不是报表风
- 成就系统可以引入更明显的收藏徽章语义
- 分享图导出时，可从详情页主视觉自然延展
